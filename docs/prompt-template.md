# 实现功能的提示词模板

> 用途：要向编码代理提一个「实现某功能」的需求时，复制下面模板、填掉 `<>`
> 占位符即可。 仓库的结构约定（新建模块、`DEFAULTS` + 幂等
> `setup()`、命令命名、自检清单）都在 `AGENTS.md` 第 3 / 5 / 6
> 节，本模板不重复它们，只负责**把需求写清楚**。

## 模板

```markdown
# 需求：<一句话功能名>

## 实现前提

- 实现前先想清楚：这个需求要动哪些模块、每个模块是否必要
- 非必要的部分 / 扩展功能：先抛出选项和描述给我选，不要直接做
- 等我确认最终目标之后，再开始写代码
- 目标是功能简洁：先把基础功能实现好，不顺手加花活

## 功能行为

<逐条写"什么时候出现什么"。具体到触发时机、显示位置、消失条件，而不是形容词。>

## 预留配置项

| 名称 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| <选项名> | <boolean / number / table> | <默认值> | <作用> |

## 命令

<需要哪些 `:<Command>`；Neovim 已有等价功能就包装默认实现，不要重造。>

## 键位

默认不绑，等我用 `setup({ map_keys = true })` 开启。

## 明确不做

<划清边界，挡掉顺手扩展。>

## 验收

<怎么算做完了：用哪些命令 / 操作实测，看什么现象。>
```

## 填写要点

- **功能行为**是最要紧的一节：写清「何时出现 /
  消失、放在哪、显示什么」。写「实现一个
  好看的浮动窗口」这种形容词，代理只能猜；写「诊断数量 > 0
  时在右下角出现带边框的 窗口，数量归零后消失」就无需猜
- **预留配置项**先给默认值，且默认值取「最简洁可用」那一档：配置项是留给以后的开关，
  不是把每个细节都做成选项
- **明确不做**能省一轮往返：不写边界，代理默认会顺手加花活
- 需求里**不要写实现方案**（用哪个插件、怎么写循环），除非你已经明确选定；否则等于
  替代理做决定，而它可能比你更清楚本仓库的现成写法
- 一次只提一件事。两件不相关的功能拆成两条需求，避免一次改动铺得太开
